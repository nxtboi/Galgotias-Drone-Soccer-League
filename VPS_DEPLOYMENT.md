# Galgotias Drone Soccer League (GDSL 2026) — VPS Production Deployment Guide

This guide provides end-to-end instructions for deploying the **GDSL 2026 Tournament Portal** onto any standard Linux Virtual Private Server (VPS) such as **DigitalOcean, AWS EC2, Linode / Akamai, Hetzner, Vultr, or Google Cloud Compute Engine**.

---

## 1. System Requirements & Prerequisites

### Minimum Server Specifications
- **Operating System**: Ubuntu 22.04 LTS / 24.04 LTS or Debian 11/12 (64-bit)
- **CPU**: 1 vCPU (2 vCPUs recommended for concurrent 3D rendering assets and Excel operations)
- **RAM**: 1 GB minimum (2 GB recommended)
- **Disk**: 15 GB SSD / NVMe
- **Network**: Static public IP address with standard ports `80` (HTTP) and `443` (HTTPS) open

### Initial Server Preparation (Ubuntu/Debian)
Connect to your VPS as `root` or a `sudo` user:
```bash
ssh root@YOUR_SERVER_IP
```

Update system packages and configure the firewall:
```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl wget git ufw software-properties-common

# Allow SSH, HTTP, and HTTPS through UFW firewall
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw --force enable
sudo ufw status
```

## 2. Choosing Your Deployment Method

We support two primary production methods:
1. **Method A: Docker & Docker Compose** (Recommended — isolated, zero host dependency conflicts)
2. **Method B: Native Node 22 + PM2 Process Manager** (Lightweight, instant restarts, minimal memory footprint)

---

## Method A: Docker & Docker Compose (Recommended)

### Step 1: Install Docker & Docker Compose
If Docker is not yet installed on your VPS, install Docker Engine using Docker's official script:
```bash
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo apt install -y docker-compose-plugin
```

Verify the installation:
```bash
docker --version
docker compose version
```

### Step 2: Clone or Copy Your Application
```bash
mkdir -p /var/www/gdsl
cd /var/www/gdsl
# Clone your git repository or copy the project files here
git clone <YOUR_GIT_REPO_URL> .
```

### Step 3: Configure Environment & Persistent Data
Create the persistent data directory:
```bash
mkdir -p data
chmod -R 777 data
```
Copy the environment template:
```bash
cp .env.example .env
nano .env # Optional: edit configuration variables
```

### Step 4: Build and Launch the Docker Container
```bash
docker compose up -d --build
```

### Step 5: Verify Container Health
```bash
# Check container status
docker compose ps

# Check logs
docker compose logs -f gdsl-portal

# Test health check endpoint directly
curl -i http://127.0.0.1:3000/api/health
```
You should receive:
```json
{"status":"ok","service":"gdsl-tournament-portal","uptimeSeconds":10,"timestamp":"...","nodeEnv":"production"}
```

## Method B: Native Node.js 22 + PM2 Process Manager

### Step 1: Install Node.js 22 & Build Tools
```bash
# Install Node.js 22 LTS via NodeSource
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs build-essential

# Verify versions
node -v   # Should be v22.x
npm -v
```

Install PM2 globally:
```bash
sudo npm install -g pm2
```

### Step 2: Clone or Copy the Project
```bash
mkdir -p /var/www/gdsl
cd /var/www/gdsl
git clone <YOUR_GIT_REPO_URL> .
```

### Step 3: Install Dependencies & Build Frontend
```bash
# Install all required packages
npm install

# Build the high-performance Vite frontend into /dist
npm run build
```

### Step 4: Ensure Permissions on the `./data` Directory
The app saves registered teams, Google Sheets sync queue, user queries, and `GDSL_2026_Teams_Roster.xlsx` inside `./data`:
```bash
mkdir -p data logs
chmod -R 775 data logs
```

### Step 5: Start the Application with PM2
Use the provided `ecosystem.config.cjs`:
```bash
pm2 start ecosystem.config.cjs --env production

# Save process list so it restarts automatically on VPS reboot
pm2 save
pm2 startup
# Copy and run the sudo env command generated by pm2 startup
```

### Step 6: Verify PM2 Status
```bash
pm2 status
pm2 logs gdsl-portal --lines 20
curl -i http://127.0.0.1:3000/api/health
```

## 3. Production Nginx Reverse Proxy & Free SSL (Let's Encrypt)

To serve the portal securely on standard ports 80 and 443 with your custom domain (e.g. `gdsl.example.com`):

### Step 1: Install Nginx and Certbot
```bash
sudo apt install -y nginx certbot python3-certbot-nginx
```

### Step 2: Configure Nginx Site
Copy the provided `nginx.conf` into Nginx sites:
```bash
sudo cp /var/www/gdsl/nginx.conf /etc/nginx/sites-available/gdsl
```

Edit the file and replace `your-domain.com` with your actual domain:
```bash
sudo nano /etc/nginx/sites-available/gdsl
```

Enable the site and remove default Nginx config:
```bash
sudo ln -s /etc/nginx/sites-available/gdsl /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
```

### Step 3: Issue Free SSL Certificate with Certbot
Point your domain's DNS `A` record to your VPS IP address, then run:
```bash
sudo certbot --nginx -d your-domain.com -d www.your-domain.com
```
Certbot will automatically verify ownership, install SSL certificates, and configure HTTPS renewal.

Test auto-renewal:
```bash
sudo certbot renew --dry-run
```

## 5. Persistent Data & Backups

All tournament data is stored in the `./data/` directory:
- `GDSL_2026_Teams_Roster.xlsx` — Live official tournament team roster workbook.
- `teams_store.json` — JSON store of all registered team profiles, rosters, and documents.
- `queries_store.json` — User inquiries and contact form submissions.
- `sheets_config.json` — Google Sheets cloud sync state.

### Recommended Daily Backup Cron Job
To create an automated daily backup of the tournament data to `/var/backups/gdsl`:
```bash
sudo crontab -e
```
Add the following line (runs every night at 2:00 AM):
```cron
0 2 * * * tar -czf /var/backups/gdsl_data_$(date +\%F).tar.gz -C /var/www/gdsl data
```

## 7. Troubleshooting & FAQs

### Problem: Application returns 502 Bad Gateway in Nginx
**Solution**: The Node backend on port 3000 is not running or is still compiling:
- Docker: run `docker compose ps` and `docker compose logs -f gdsl-portal`.
- PM2: run `pm2 status` and `pm2 logs gdsl-portal`.
- Verify port binding: `sudo netstat -tlpn | grep 3000` or `ss -tulpn | grep 3000`.

### Problem: Uploaded payment proof or logo throws 413 Payload Too Large
**Solution**: Ensure `client_max_body_size 25M;` is present in your `/etc/nginx/sites-available/gdsl` configuration block, then run `sudo nginx -s reload`.

### Problem: Changes to Excel or Teams do not persist after container restart
**Solution**: Ensure the volume `- ./data:/app/data` is present in your `docker-compose.yml` so data is preserved on the host filesystem.
